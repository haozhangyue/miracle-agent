# Miracle P2 双轨原型共同设计简报

> 用途：为 Product Design 与 Pencil 两条独立原型线提供完全一致的产品输入，确保后续
> 对比关注设计质量，而不是需求理解差异。
>
> 当前产品基线：`16_融合_产品信息架构与设计图规划.md`

## 1. 设计目标

为 Miracle 本地优先 Agent OS 制作第一轮桌面端原型，验证用户能否完成：

```text
首页
-> 新任务
-> Validate / Dry-run
-> Run 工作区
-> TTS 节点 blocked
-> Attention Queue
-> 母稿审核
-> 驳回并创建新 Attempt
```

本轮不验证完整 Workflow Builder、Infinite Canvas、Agent Center、资源库和正式交付中心。

## 2. 目标用户

- 一人公司操作者：希望用推荐流程快速完成复杂内容生产任务。
- 任务发起者：关注任务是否按计划运行、是否需要自己处理。
- 工作流设计者：需要理解 Run 快照和 Workflow 编辑态的边界。
- 审核者：需要确认产物版本、证据和下游影响后作出审核决定。

## 3. 共同页面范围

| Frame ID | 页面 | 必须表达的核心信息 |
|---|---|---|
| `P2F-01` | 首页 | 待我处理、继续运行、快速启动、最近交付、系统风险 |
| `P2F-02` | 新任务 | 任务描述、工作流选择方式、执行策略、输入和输出要求 |
| `P2F-03` | Validate / Dry-run | 节点、Agent、Gate、凭证、成本、风险、产物预估 |
| `P2F-04` | Run 工作区 | Run 状态、固定视图、动态阶段过滤器、只读快照、节点状态 |
| `P2F-05` | Attention Queue | 根因聚合、影响对象、恢复动作、生命周期和优先级 |
| `P2F-06` | 审核抽屉 | 产物版本/hash、Gate、证据、下游影响、批准/驳回/返工 |

## 4. 共同产品规则

### 4.1 导航

一级导航统一使用：

```text
首页 / 任务运行 / 工作流 / 智能体 / 审核与交付 / 资源库 / 设置
```

首页主按钮为“新任务”。

### 4.2 启动术语

工作流选择方式：

```text
推荐模板 / 从模板自定义 / AI 生成草案
```

执行策略：

```text
Auto / Manual / Hybrid
```

两者不得混为同一组选择。

### 4.3 状态归属

界面不得只显示无主语状态，统一使用：

```text
AgentHealth · waiting
NodeRun · blocked
NodeRun · failed
NodeAttempt · failed
GateInstance · pending_review
ArtifactManifest · pending_review
```

### 4.4 Run 边界

- Run 展示冻结的 `WorkflowSnapshot`。
- 当前 Run 中不允许直接修改工作流结构。
- MVP 只提供“基于当前快照创建 Workflow draft”。
- 不提供 Run patch。

### 4.5 Attention Queue

- 一个根因对应一个主 Attention Item。
- Agent、Node、Artifact 和 Gate 作为关联对象展开。
- 底层权威状态恢复后自动进入 resolved。
- 未完成审核、对账和危险操作确认不可隐藏。
- 已解决项目进入历史记录，不直接删除。

### 4.6 Run 导航

- 固定页面视图：总览 / 流程 / 协作 / 产物 / 时间线 / 审计。
- 流程阶段来自 WorkflowSnapshot 动态生成。
- 阶段控件只过滤或聚焦当前视图，不构成第二套页面导航。
- 通用界面不得硬编码 Flow A-G，但样例数据可以显示内容生产阶段名称。

## 5. 共同样例数据

任务：

```text
制作一期 Codex 与 Claude Code 最新动态的中文内容包
```

工作流：

```text
content-production-v0 · version 0.6
```

关键节点：

| 节点 | 状态 | Agent | 产物或问题 |
|---|---|---|---|
| 情报采集与事实核验 | done | intelligence-agent | clean_events.json |
| 内容 MD 母稿 | pending review | content-agent | md_master_v2.md |
| 脚本与分镜 | queued | script-agent | 等待母稿批准 |
| TTS 与字幕 | blocked | tts-agent | 缺少 VOLC_TTS_API_KEY |
| 视频渲染 | waiting | video-agent | 等待音频和字幕 |
| 分发复盘 | queued | distribution-agent | 尚未开始 |

TTS 根因：

```text
NodeRun · blocked
原因：缺少 VOLC_TTS_API_KEY
影响：视频分支无法继续；Markdown 分发不受影响
恢复动作：配置凭证 / 切换 Provider / 跳过可选视频分支
```

审核对象：

```text
ArtifactManifest: md_master_v2
version: 2
hash: sha256:8c21...a49e
GateInstance: gate-md-master-002
status: pending_review
```

## 6. 共同视觉约束

- 桌面端工作台，目标尺寸 `1440 × 960` 或 `1440 × 1024`。
- 安静、专业、适合高频扫描的运营控制台，不做营销首页。
- 信息密度中高，但依靠分组、对齐、排版和分隔线建立层级。
- 不使用卡片套卡片，不把每个列表项都做成漂浮卡片。
- 状态不能只依赖颜色，必须同时提供图标或文字。
- 主色不采用单一紫色、深蓝或米黄色统治整个界面。
- 按钮优先使用熟悉图标；陌生图标需要 tooltip。
- 文字不得溢出或重叠。

## 7. 两条交付线

### 7.1 Product Design 线

- 生成恰好 3 个独立视觉方向。
- 每个方向至少用一个完整桌面界面表达整体设计语言。
- 三个方向必须在信息层级、布局策略或交互模型上有实质差异。
- 输出概念名、核心取舍、适合场景和风险。
- 本轮只产出视觉候选，不把候选直接实现为代码。

### 7.2 Pencil 线

- 创建可编辑 `.pen` 文件。
- 至少包含 `P2F-01` 至 `P2F-06` 六个 Frame。
- 建立共享 App Shell 和核心组件。
- 串联可点击主链路。
- 使用低保真或中低保真表达，不提前锁死品牌高保真视觉。

## 8. 对比评审维度

| 维度 | 关注问题 |
|---|---|
| 主任务清晰度 | 用户是否能快速找到下一步行动 |
| Run 共同上下文 | 页面切换时是否持续保留 Run、对象和状态 |
| 状态可理解性 | 是否清楚区分 Agent、NodeRun、Attempt、Gate 和 Artifact |
| 异常恢复 | TTS blocked 是否能找到正确且安全的处理动作 |
| 审核安全性 | 是否能确认版本、hash、Gate 和下游影响 |
| 导航一致性 | 固定视图和动态阶段过滤是否互不冲突 |
| 信息密度 | 是否适合频繁监控，而不是展示型页面 |
| 扩展能力 | 后续加入 Agent 协作、DAG、Canvas 时是否有空间 |
| 可访问性 | 状态、焦点、实时变化和列表替代方案是否可理解 |
| 实现可行性 | 是否能映射到现有对象模型和本地 Web 架构 |

## 9. 独立性约束

两条设计线只共享本文和当前有效产品文档，不互相读取交付结果。完成后由主任务统一检查、
截图和编写比较结论。
