## 1. 评审原则

- 先判断产品结构和任务闭环，再判断视觉完成度。
- Product Design 图片优先用于判断最终界面的视觉方向、布局策略、信息层级和交互重心。
- Pencil 原型用于校验页面关系、对象语义、状态完整性、审核安全和六页任务闭环。
- 两类交付物媒介不同，不直接用像素精细度比较优劣。
- 任何方案若违反 WorkflowSnapshot 不可变、状态归属或审核安全边界，应直接记录为
  结构问题，不用视觉优点抵消。
- 下一轮融合原型默认采用“Product Design 主导视觉体验，Pencil 提供结构约束”的工作方式。

## 2. 评分标准

每项使用 1-5 分：

| 分数 | 含义 |
|---:|---|
| 1 | 无法完成任务或违反核心产品规则 |
| 2 | 可以辨认，但存在明显阻碍或高误操作风险 |
| 3 | 基本可用，需要局部调整 |
| 4 | 清晰、稳定，只有少量优化点 |
| 5 | 明显降低理解和操作成本，可作为后续基线 |

## 4. 主任务走查

### T1 首页发现下一步行动

- 是否优先显示需要用户决定或修复的事项。
- 是否能区分“继续运行”和“新任务”。
- 是否避免用无行动意义的对象总数占据首屏。

### T2 新任务与 Dry-run

- 是否明确区分工作流选择方式与执行策略。
- 是否展示凭证、Gate、Provider、成本、风险和产物，而非只显示“检查通过”。
- 是否能在启动前修复问题或返回调整。

### T3 Run 中处理 TTS blocked

- 是否显示 `NodeRun · blocked`。
- 是否说明视频分支受阻但 Markdown 分发不受影响。
- 是否提供配置凭证、切换 Provider、跳过可选分支等安全动作。
- 是否保持当前 Run、节点和影响范围上下文。

### T4 Attention Queue

- 是否按根因聚合，而不是重复生成 Agent、Node 和 Artifact 告警。
- 是否能看到优先级、等待时长、影响和恢复动作。
- 是否区分可暂缓提醒和不可关闭的审核、对账、危险确认。

### T5 母稿审核返工

- 是否显示 Artifact version/hash 和 GateInstance。
- 是否展示证据和下游影响。
- 驳回是否创建新 revision/Attempt，而不是覆盖已审核版本。
- 操作后是否能返回原 Run 并理解下一状态。
