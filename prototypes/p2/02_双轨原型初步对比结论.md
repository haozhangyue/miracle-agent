# Miracle P2 双轨原型初步对比结论

> 结论性质：设计团队内部预评审，不替代后续人工评审和目标用户可用性测试。

## 1. 总体结论

两条原型线不是互斥方案，当前最合理的融合方向是：

```text
Product Design A 的行动优先首页
+ Product Design B 的 Run 驾驶舱结构
+ Product Design C 的根因联动态势模型
+ Pencil 的六页任务闭环、状态归属和审核安全约束
```

下一轮融合原型应明确采用：

```text
Product Design 主导视觉方向、页面布局和交互体验
+ Pencil 校验流程完整性、对象语义、状态归属和安全边界
```

Product Design 的优势是快速拉开视觉层级和交互重心，更适合作为最终界面体验的主参考；
Pencil 的优势是把当前对象模型、状态归属和六页链路落实为可编辑设计，更适合作为结构
校验底稿。现阶段不建议选一张 Product Design 图直接覆盖全产品，也不建议把 Pencil 当前
视觉直接定义为最终高保真风格。

## 3. Product Design 三个方向

三张 Product Design 图不是三个完整产品方案，也不是三个首页二选一。它们分别对应不同
页面职责：

| 方向 | 推荐定位 | 是否作为默认首页 |
|---|---|---|
| Product Design A：行动中枢 | 默认首页 / 任务工作台 | 是 |
| Product Design B：Run 驾驶舱 | Run 工作区 / 执行监控页 | 否 |
| Product Design C：态势与处置台 | Attention Queue / 异常处置 / 后续 Agent Collaboration | 否 |

因此推荐组合不是在 A 和 C 中选一个，而是让 A 负责入口和行动优先级，让 C 负责根因、
依赖、Agent/Node/Artifact 联动处置。

### A 行动中枢

适合作为默认首页视觉基线：

- “待我处理”优先级最高，符合任务型首页定位。
- 右侧恢复动作能减少从异常摘要到处置页面的跳转成本。
- 继续运行、快速启动、最近交付和系统风险层级完整。

需要控制：

- 首页信息量高，Attention 必须严格去重。
- 右侧详情不能常驻挤压主内容，应允许收起或按选择出现。

### B Run 驾驶舱

适合作为 Run 工作区视觉基线：

- Run 状态、快照、成本、耗时和 Attention 始终保留。
- 固定视图、动态阶段过滤器和节点详情的关系清晰。
- WorkflowSnapshot 只读和恢复动作表达准确。

需要控制：

- 三栏布局认知负担最高。
- 右侧详情应根据节点选择出现，并在窄屏降级为抽屉。
- 运行对象术语需要分层展示，避免新用户首屏接触过多 ID。

### C 态势与处置台

适合作为 Attention Queue 和后续 Agent Collaboration 的参考：

- 一张主 Attention Item 联动 Agent、Node、Artifact 和下游依赖。
- 适合验证根因聚合、影响分析和安全恢复动作。
- 多 Agent 并发、等待和交接关系比普通列表更容易理解。

需要控制：

- 不适合作为全产品默认首页。
- 正常运行任务和创建新任务的入口较弱。
- 必须确保态势图有列表替代视图，满足可访问性和高密度场景。

## 4. Pencil 六页原型

当前 Pencil 方案适合作为结构校验底稿，而不是最终视觉主方案：

- 六个核心页面覆盖了第一轮完整任务闭环。
- 工作流选择方式与执行策略已经分离。
- Dry-run 在启动前明确暴露凭证、Gate、风险、成本和可选分支。
- Run 页面准确表达固定视图、动态阶段过滤和只读快照。
- Attention 页面落实根因聚合与关闭规则。
- 审核抽屉保留 Artifact version/hash、Gate、证据和下游影响。

当前不足：

- 视觉层级仍偏低保真，状态密度和主次关系可继续借鉴 Product Design。
- 主链路以页面关系表达，尚未形成真实可操作的代码级点击体验。
- 首页右侧详情、Run 右侧上下文和 Attention 关联态势还可以更动态。

## 6. 暂不进入融合的设计

- 不把 Product Design C 设为默认首页。
- 不在首轮同时展示永久三栏、底部事件抽屉和复杂依赖图。
- 不因为视觉图出现某个字段，就把它视为正式协议字段。
- 不在 P2 恢复 Run patch。
- 不把 Agent Collaboration 强行并入本次审核返工测试。

## 7. 人工评审重点

下一轮人工评审不需要重新讨论已确认的产品边界，只需要围绕以下 4 组问题做选择，并补充
必要意见。默认建议已标注，可直接采用，也可以按实际偏好调整。

### 7.1 首页采用 Product Design A 到什么程度

选择类型：单选。

| 选项 | 决策 | 影响 |
|---|---|---|
| A1 推荐 | 采用 Product Design A 作为首页主视觉和主布局。 | 首页以“待我处理、继续运行、快速启动、最近交付”为核心，下一轮直接做融合稿。 |
| A2 | 只吸收 Product Design A 的右侧行动详情，首页主体仍按 Pencil 简化结构。 | 实现风险低，但视觉提升有限。 |
| A3 | 采用 Product Design A 的首页框架，但降低首屏信息密度。 | 更适合 MVP，Attention 数量和系统风险摘要需要收敛。 |
| A4 | 暂不确定首页，补一轮 Product Design 首页变体。 | 延长设计周期，适合当前对首页信息密度仍不满意的情况。 |

### 7.2 Run 工作区采用 Product Design B 到什么密度
