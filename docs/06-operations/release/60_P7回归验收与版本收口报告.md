## 1. 最终结论

P7 已完成 Codex 多节点连续执行、Artifact 交接、Gate 暂停/批准恢复、retry、Provider
Driver、fallback 和可观测性工程交付。脱敏的 `codex-content-chain-v0` 已在仓库外隔离
workspace 完成 B/C 连续执行、C Gate 暂停、批准后 D 恢复的真实 Codex 闭环。

工程回归、真实 Codex 闭环和 Web 验收通过，故 P7-10 是条件通过；但 DeepSeek、Kimi 和
MiniMax 的真实凭证均未设置，未发起任何真实 Provider 请求，至少一个真实 Provider 脱敏
smoke 的硬发布门未满足。fake provider 只证明错误处理和路由工程行为，不能替代真实
Provider smoke。

因此不升级版本，继续使用 `v0.8.0`；`p7-10`、P7 和 L3 保持 `current`，不创建 P8 或其他
下一阶段当前节点。本报告是 P7-10 当前发布判断的唯一真相源。

## 6. 发布决策

`v0.8.0` 继续有效，不创建 `v0.8.1` 或新的 P8 当前节点。P7 不能标为 completed，原因只
有一个：至少一个经明确授权的真实 Provider 脱敏 smoke 尚未成功。

恢复发布门的唯一动作是：在显式授权下提供一个 Provider 凭证，设置
`MIRACLE_ENABLE_MODEL_API=1`，于仓库外隔离 workspace 运行单 Provider 脱敏 smoke；成功前
不得将任一内置 Profile 标为 `healthy`。
