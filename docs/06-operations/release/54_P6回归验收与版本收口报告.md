## 1. 最终结论

P6 三条工程轨道已经在同一套 Miracle 系统中闭环：

```text
真实 W24/W23 historical importer 与只读投影
        +
RunDraft / Dry-run / LaunchConfirmation
        +
Codex CLI Adapter / 隔离 Attempt / 正式 NodeRun
        -> Markdown Artifact -> pending Gate -> TraceEvent
```

P6-08 未发现阻断发布的真实性、安全或兼容性问题。验收中发现“事件与审计”在长
Run/Node/Artifact ID 下出现列文本重叠，已在本轮修复并重新完成页面截图验证。

版本升级条件全部满足，因此项目从 `v0.7.0` 升级为 `v0.8.0`。P6 的完成不代表
Miracle 已具备多节点真实连续执行、官方 API Adapter、云端多租户或商业计费能力。

## 7. 版本决策

发布 `v0.8.0 真实工作流工程接入基线`，依据如下：

1. Historical importer 可读取真实 W24/W23，并保持源目录只读。
2. Historical Run 已可在 Web 中跨 Run 查看全部核心对象。
3. RunDraft、Dry-run 和人工确认已进入可操作界面。
4. Codex CLI 已完成真实单节点执行，并形成 Artifact/Gate/Trace。
5. 多 Domain、失败、取消、超时、幂等和崩溃恢复已有自动化回归。
6. 用户手册、版本历史、导航、截图和 task-baseline 同步更新。

## 8. 当前边界与下一步

`v0.8.0` 仍有以下明确边界：

- 真实执行仅开放 `C_md_master` 单节点实验模板。
- 多节点真实连续执行、重试/fallback 和跨 Adapter 调度尚未开放。
- 官方 API、Hermes、OpenClaw Adapter 尚未实装。
- 真实执行默认关闭，必须显式设置 `MIRACLE_ENABLE_REAL_CODEX=1`。
- Node.js 仍是 Local Sidecar，不是最终商业化云端主后端限定。

下一任务进入 `P7-01 多节点真实执行与 Adapter 扩展规划`，先形成范围与协议评审，不在
P6-08 中直接扩展执行能力。
