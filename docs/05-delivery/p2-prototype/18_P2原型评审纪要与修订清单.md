# 18_P2原型评审纪要与修订清单

> 文档状态：P2 Web 原型评审纪要
>
> 评审对象：`prototypes/p2/fusion-clickable/`
>
> 评审日期：2026-06-26
>
> 结论：P2 原型评审完全通过；原问题项临时备忘，后续产品成型或正式实现时再判断是否调整，不阻断 P3 技术详细设计。

## 1. 评审范围

本轮只评审当前 Web 工作台原型，不进入 P3 技术详细设计。

评审问题：

1. 首页是否能快速判断“我现在该处理什么”。
2. Run 工作区是否清晰表达执行状态、节点、右侧详情、事件审计。
3. Attention 是否能表达根因、关联对象、恢复动作。
4. 主链路通过后，是否需要补充独立 Agent Collaboration 原型。

## 2. 总体结论

当前 Web 原型已经能支撑 P2 主链路验收：

- 首页能让用户先看到待处理事项、继续运行任务和推荐启动入口。
- Run 工作区能表达当前 Run 状态、节点状态、右侧节点详情和事件审计。
- Attention 能把异常从“状态列表”提升为“根因、影响范围、关联对象、恢复动作”的处置视图。
- 多 Agent 协同已经补充为独立 `P2F-07 Agent Collaboration` 页面，当前挂在“智能体”导航下。

补充评审后，原先列出的交互语义问题不再作为 P2 阻塞项。本轮建议：

```text
P2 原型完全通过
-> 问题项进入后续设计备忘 / P3 实现关注项
-> 进入 P3 技术详细设计
```

## 3. 通过项

### 3.1 首页：通过

首页已经能回答“我现在该处理什么”。

证据：

- 首屏最高优先级是“待我处理”，不是对象统计或系统介绍。
- 待处理表格按优先级、事项、类型、所属对象、状态、影响范围和操作组织。
- 选中的 TTS 凭证问题在右侧详情中展示根因、影响范围、恢复动作、相关对象和时间线。
- “继续运行”能告诉用户当前 Run 进度、阶段、状态和进入方式。
- “快速启动”放在待处理和继续运行之后，优先级符合操作台场景。

评审判断：

首页已经具备行动中枢能力。用户第一次进入时能判断当前最该处理的是
`TTS 缺凭证` 或 `母稿待审核`，而不是先理解全套系统对象。

### 3.2 Run 工作区：通过

Run 工作区已经能表达执行状态、节点、详情和审计。

证据：

- 顶部 Run 摘要展示 Run 名称、Run ID、`Run · running`、`WorkflowSnapshot · v0.6 · 只读`、
  Attention 数量、运行时长和成本。
- 中间流程视图按节点展示 Agent、NodeRun 状态和 ArtifactManifest。
- 右侧详情展示选中节点的 Agent、Provider、NodeRun ID、Attempt、根因、影响和恢复动作。
- 底部“事件与审计”展示最近事件，能说明状态变化来源。
- 左侧阶段过滤明确标注“非导航”，降低与页面导航混淆。

评审判断：

Run 主视图成立。用户能看懂“当前卡在 TTS 与字幕节点，原因是缺凭证，下游视频等待，
但 Markdown 分发不受影响”。

后续设计备忘：

- Run 页顶部 Tab 视觉上像可切换页面，但当前只是静态选中态。P2 需要决定：
  要么补齐 Tab 点击后的内容切换，要么在原型范围里明确只验证“流程”Tab。
- “查看详情”“暂停”“更多”等按钮还没有定义点击后的安全反馈。P2 至少要明确这些是
  真实动作、抽屉入口还是占位入口。

### 3.3 Attention：通过

Attention 已经能表达根因、关联对象和恢复动作。

证据：

- Attention Queue 把问题按“需要决定、需要修复、需要校对、需要关注”聚合。
- 选中项展开后展示原因、影响、影响范围、关联 Run 和相关对象。
- 右侧“智能体协作与依赖态势”把 Agent、Node、Artifact 状态放在同一上下文里。
- 当前选中对象下方提供“影响下游节点”“关联产物”“在流程中定位”。

评审判断：

Attention 不再只是告警列表，已经接近 Miracle 需要的“处置台”形态。

后续设计备忘：

- 恢复动作需要补充安全边界。例如“跳过可选视频分支”应该明确只影响视频分支，
  不应改变 required 主链路。
- “静音 30 分钟”是通知动作，不是恢复动作。建议在 UI 上与“配置凭证、切换 Provider、
  跳过分支”分组，避免用户误认为静音可以修复问题。
- Attention 项的生命周期需要在原型中体现最小状态流：
  `open -> acknowledged/snoozed -> resolved`，否则 P3 不容易设计队列去重和关闭协议。

### 3.4 P2F-07 Agent Collaboration：已补充

由于多 Agent 协同是 Miracle 核心差异点，本轮已新增独立页面原型：

```text
prototypes/p2/fusion-clickable/src/App.jsx
-> “智能体”导航
-> P2F-07 Agent Collaboration
```

正式预览图：

```text
assets/prototypes/fusion-clickable/agent-collaboration-desktop.png
```

该页面补充表达：

- 当前 Run 的 Agent 协同链路。
- 每个 Agent 的职责、状态和交接输出。
- 选中 Agent 的交接合同、上游输入、当前风险和下游影响。
- 恢复动作必须绑定对象和安全边界。
- 关键事件说明 Agent 状态变化来自运行事实，而不是静态配置。

评审判断：

P2F-07 解决了原型里“多 Agent 协同只藏在 Attention 右侧态势里”的问题。现在用户可以从
一级“智能体”入口看到 Miracle 的核心差异点。

## 4. 后续设计备忘

| 编号 | 问题 | 影响 | 建议处理 | 阶段 |
|---|---|---|---|---|
| P2-REV-01 | Run 顶部 Tab 看起来可点击，但当前没有切换内容 | 用户可能误判“协作/产物/时间线/审计”已经可验收 | 后续产品成型时补齐 Tab 点击态，或在正式实现中明确只验收“流程”Tab | 后续设计备忘 |
| P2-REV-02 | 恢复动作缺少动作结果和安全边界 | P3 可能把危险动作设计成普通按钮接口 | P3 实现设计中为配置凭证、切换 Provider、跳过分支、静音分别写清前置条件和结果 | P3 实现关注 |
| P2-REV-03 | Attention 生命周期只展示筛选，不展示状态流 | 后续队列去重、关闭、恢复语义不稳 | P3 Attention 协议中定义 open、acknowledged、snoozed、resolved | P3 实现关注 |
| P2-REV-04 | P2F-07 中部分交接信息偏密 | 可读性可以继续提升 | 后续视觉打磨时压缩长 artifact 名称或增加 hover/详情抽屉 | 后续设计备忘 |
| P2-REV-05 | 键盘路径和读屏语义未完整验证 | 不能声明无障碍通过 | P3 正式实现时补键盘、ARIA、焦点顺序和对比度检查 | P3 实现验收 |

以上项目不阻断 P3 技术详细设计；进入 P3 后作为接口安全边界、状态协议和实现验收项处理。

## 5. 延后项

以下内容不阻塞 P2 主链路，不应在当前阶段展开：

| 延后项 | 延后原因 | 进入阶段 |
|---|---|---|
| 移动端 / APP 适配 | 当前决策已经限定 Web 工作台，不验证窄屏 | P3 后或独立移动端设计 |
| 完整 Workflow Builder | P2 当前验证运行与处置主链路，不验证编辑器全能力 | P3/P4 |
| 资源库完整安装升级流程 | 不影响首页、Run、Attention 主链路 | P3/P4 |
| 真实后端接口和数据持久化 | P2 是交互原型，不做技术详细设计 | P3 |
| Agent 容量、并发、调度算法 | P2 只表达协同态势，不定义完整执行协议 | P3 |
| 完整审计检索和日志查询 | 当前只验证事件审计露出位置 | P3/P4 |

## 6. P2 与 P3 分界

### 6.1 P2 已解决

P2 需要解决的是产品语义和主链路体验：

1. 用户进入首页能判断下一步处理什么。
2. 用户进入 Run 能看懂当前执行到哪里、哪个节点异常、右侧详情是什么。
3. 用户进入 Attention 能看懂根因、影响范围、关联对象和安全恢复动作。
4. 多 Agent 协同有独立入口和最小可理解页面。
5. Run/Attention 中出现的关键动作已经具备可理解入口；动作协议进入 P3 详细设计。

### 6.2 进入 P3 解决

P3 解决技术详细设计，不应替 P2 补产品语义：

1. Route、状态管理、数据加载和页面权限。
2. Run、NodeRun、NodeAttempt、AgentHealth、ArtifactManifest、GateInstance 的前端数据模型。
3. Attention Queue 的后端事件投影、去重、关闭和恢复协议。
4. Agent Collaboration 的真实依赖图、Agent 心跳、容量和调度接口。
5. 事件审计查询、日志分页和持久化。
6. 无障碍语义、键盘路径和组件级实现规范。

## 7. P2 主链路验收结论

| 主链路 | 结论 | 说明 |
|---|---|---|
| 首页判断“我该处理什么” | 通过 | 待我处理、继续运行、右侧详情能形成明确行动路径 |
| Run 执行态理解 | 通过 | 执行状态和节点详情清晰，Tab/按钮行为进入后续备忘 |
| Attention 根因处置 | 通过 | 根因、对象和动作清楚，动作安全边界和生命周期进入 P3 协议设计 |
| Agent Collaboration | 已补充 | 新增 P2F-07 Web 页面原型 |

最终判断：

```text
P2 原型评审完全通过
P2-REV-01 至 P2-REV-04 作为后续设计备忘
P2-REV-02、P2-REV-03、P2-REV-05 同步进入 P3 实现关注与验收

```
