## 3. 设计边界

- Flow A-G 是 `content-production` Domain 的真实样本，不进入 Miracle 核心模型硬编码。
- 历史 Run 导入必须区分“真实事件”和“只读 projection”；缺少事件证据时不能伪造 TraceEvent。
- P5 第一轮不执行真实 Runner，不调用 Codex、OpenAI API、HyperFrames、TTS 或 Pencil。
- 真实媒体产物只记录本地路径、hash、类型、版本和预览能力，不复制大文件进 fixture。
- W24 为主样本，W23 用于验证规则泛化；后续新增真实交付包时应复用同一映射规则。

## 5. 依赖与并行

```text
P5-01 -> P5-02 -> P5-03 -> P5-06 -> P5-07 -> P5-08 -> P5-09
                 -> P5-04 -> P5-05 -> P5-06
```

- `P5-01` 和 `P5-02` 是串行基础，不能跳过。
- `P5-03` 和 `P5-04` 可在 `P5-02` 后并行。
- `P5-05` 以 `P5-04` 为前置，避免 Trace 映射跳过 GateDecision 和审核证据边界。
- `P5-06` 依赖历史 Run、Gate 和 Trace 映射完成。
- `P5-08` 的候选调研可在 `P5-06` 后并行，但最终边界验收依赖 `P5-07` 的统一启动协议。

## 6. 验收标准

- 能明确列出 W24 和 W23 的真实控制文件、产物文件、审核文件和缺口。
- 能把 Flow A-G 表达为通用 WorkflowSpec，不新增 Flow 专属核心字段。
- 能把真实产物映射为 ArtifactManifest，并保留本地路径、类型、版本和预览策略。
- 能把审核策略映射到 GateSpec/GateInstance/GateDecision，不把审核状态塞回 NodeSpec。
- 能把已有 task trace/event 映射为 TraceEvent；没有证据的历史状态只能作为 projection。
- task-baseline 显示 P5、P6-01 和 P6-02 已完成，当前任务进入 `P6-03`。
- 每次 P5 提交后同步更新 `plans/mvp-task-baseline/roadmap.json` 并说明同步状态。

## 7. 暂不做事项

- 不直接执行真实内容生产 Runner。
- 不调用真实 Codex、OpenAI、TTS、HyperFrames 或 Pencil。
- 不把历史媒体大文件复制进 Miracle fixture。
- 不做云端、多租户、账号、计费或团队协作。
- 不把“热点工具更新”的目录命名硬编码为 Miracle 通用模型字段。
