# 59 P7-09 多运行时 UI 与可观测性交付说明

## 1. 交付范围

P7-09 保持既有 Product Design A/B/C 和信息架构：Run 使用 B 的高密度工作台，Attention 使用 C 的根因处置面。未新增 Provider 一级页面，也未新增移动端适配。

- Run 的 Node Detail 展示 `Runtime`、Provider Profile、model、完整 NodeAttempt 历史、operation 内 retry/fallback 关系、usage、估算/实际成本和 retry 倒计时/预算。
- Scheduler 观察区展示最后 tick、就绪节点、暂停 reason code 与下一建议动作。
- Artifact Board 展示 Artifact 的版本、hash 与 WorkflowSpec 声明的消费者。
- Attention 仅显示可执行动作：查看 retry budget、停止自动重试、确认 fallback、打开凭证配置说明和返回 Run。

## 2. API 与真相边界

`GET /api/v0/runs/:runId/observability` 是只读聚合投影，读取 NodeAttempt、ProviderRoutingDecision、RetrySchedule、ArtifactManifest、事件和 ExecutionPlan；它不写入 Run 事实。返回仅含 ID、状态、reason code、usage、成本、版本/hash 和消费者，不返回 prompt、Artifact 正文、attempt workspace、绝对 runtime 路径或 credential。

`POST /api/v0/runs/:runId/nodes/:nodeRunId/retry/stop` 在 Run mutation lock 内把活动 retry 转为带 `auto_retry_stopped` reason code 的 terminal retry state，并由 Orchestrator 提交 `retry_exhausted`/Attention 审计效果；Web 不直接写 JSON。

跨 kind fallback 在 Attention 先展开精确 `decision_id`、`operation_id`、NodeRun、current kind 与目标 Profile，再由第二个“确认并提交”动作调用既有 fallback confirmation API。服务端继续核对当前 Decision revision、Attempt、RetrySchedule 与目标 Profile，陈旧或误触请求返回 `409 routing_decision_not_current`。
