## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 抽象过大，迟迟不能落地 | 先用热点工具更新 Flow A-G 做第一条样本。 |
| 全部节点化导致使用成本高 | 默认组件库 + 推荐模板，高级模式再开放细节。 |
| 双视图数据割裂 | 统一 Workflow Graph，视图只存 layout。 |
| 多平台 adapter 太复杂 | 先定义接口，同步设计，分阶段接入。 |
| Auto 模式不可控 | 高风险节点保留审核门，进化建议需人工批准。 |
| 媒体产物过大 | 本地路径/外部链接记录，不进入核心数据库或 Git。 |
| Agent 状态黑箱 | 强制 TraceEvent 和 AgentRun 记录。 |
| 技术选型过晚导致原型返工 | P1.5 前置技术架构选型与系统架构图。 |
| 产品设计图缺位导致界面范围发散 | P2 先产出产品信息架构图和页面地图，再做高保真原型。 |
