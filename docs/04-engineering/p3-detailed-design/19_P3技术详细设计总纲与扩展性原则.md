# 19_P3技术详细设计总纲与扩展性原则

> 文档状态：P3 技术详细设计总纲。
>
> 前置结论：P2 原型评审完全通过，`18_P2原型评审纪要与修订清单.md` 中的问题项进入后续设计备忘和 P3 实现关注项，不阻断 P3。
>
> 核心约束：Miracle 是通用 Agent OS，不是资讯内容生产专用系统；`content-production` 只是第一个样本 Domain。

## 1. P3 目标

P3 的目标不是重新讨论产品定位或技术选型，而是把已经通过的架构、产品 IA 和原型落成工程可实施的详细设计。

P3 需要回答：

1. Miracle MVP 如何用本地 Web + Local Sidecar 跑起来。
2. 工作流、节点、Agent、组件库、Provider、Artifact、Attention 如何保持领域无关。
3. 当前 Web 原型的页面如何映射到数据模型和 API。
4. 本地 MVP 如何保留商业化云端控制平面、Worker、队列和数据库演进空间。
5. MVP 任务如何拆成可执行工程单元。

P3 不做：

1. 不创建正式前端/后端代码工程。
2. 不实现真实 Runner。
3. 不做账号、多租户、计费、云同步。
4. 不把 Node.js 本地服务设计成最终商业后端。
5. 不把 Flow A-G 写死为系统内置唯一流程。

## 2. 产品和工程定位

Miracle 的工程定位：

```text
通用 Agent OS
-> 本地优先 MVP
-> 可演进到商业化云端控制平面
-> 通过 DomainPack / WorkflowTemplate / ComponentLibrary 支持不同岗位和业务
```

第一条样本是：

```text
content-production
-> 热点工具更新 Flow A-G
```

但核心模型必须能同样表达：

| Domain | 示例任务 | 关键产物 |
|---|---|---|
| `content-production` | 资讯内容生产、短视频内容包、平台分发 | markdown、script、audio、video、publish_package |
| `image-generation` | 生图、风格探索、批量变体 | prompt、image、upscale_result、review_note |
| `video-production` | 视频脚本、分镜、TTS、剪辑、渲染 | storyboard、audio、caption、video |
| `script-writing` | AI 剧本、人设、分集大纲、分镜 | character_sheet、outline、episode_script |
| `research-analysis` | 研究问题、资料采集、事实核验、报告 | dataset、evidence_table、report、citation |
| `sales-ops` | 客户线索、话术生成、跟进计划、复盘 | lead_list、message_pack、crm_note |
| `customer-quality` | 客服质检、问题归因、改进建议 | transcript、scorecard、issue_cluster |

## 3. 架构边界

### 3.1 MVP 本地架构

MVP 采用：

```text
Browser UI
-> Local Sidecar API
-> Local Project Files / Registry / Run Trace / Adapter
```

职责：

| 层级 | MVP 方案 | 职责 |
|---|---|---|
| UI | React + Vite + TypeScript | 首页、Run、Attention、Agent Collaboration、Artifact、Gate Review |
| Local Sidecar | Node.js / TypeScript | 本地文件读写、validate/dry-run、CLI/MCP/API adapter、本地 trace |
| Storage | YAML/JSON/JSONL + manifest | WorkflowSpec、Registry、Run 事件、Artifact 索引 |
| Adapter | CLI / HTTP / MCP | Codex、Hermes、OpenClaw、官方 API、Pencil、HyperFrames 等能力接入 |

### 3.2 商业化后端演进

`Node.js Local Sidecar` 不是最终商业后端限定。

商业化阶段建议拆为：

| 平面 | 建议技术 | 职责 |
|---|---|---|
| Cloud Control Plane | Java/Kotlin、Go 或同等级后端栈 | 用户、组织、多租户、权限、计费、Registry、Run 调度、审计 |
| Worker Plane | Python Worker、Node Worker、远程 API Worker | AI/数据处理、模型调用、文档解析、专用工具适配 |
| Queue | 云端任务队列 | 长任务排队、限流、幂等、重试、失败对账 |
| Data Plane | PostgreSQL + Object Storage + Event Journal | 租户数据、运行索引、审计事件、产物引用 |
| Local Sidecar | Node.js / TypeScript | 用户本机文件、CLI、MCP、Keychain/env 引用、本地 runtime |

P3 文档只能把这些边界预留清楚，不提前实现云端平台。

## 4. 扩展性原则

### 4.1 领域无关

核心对象不得出现只属于 Flow A-G 的字段名。

错误示例：

```yaml
node:
  md_master_required: true
  tts_video_branch: optional
```

正确示例：

```yaml
node:
  inputs:
    - id: approved_primary_artifact
      kind: artifact
      required: true
  outputs:
    - id: generated_media
      kind: artifact
      required: false
```

领域差异进入：

1. `DomainPack`。
2. `WorkflowTemplate`。
3. `ComponentLibrary`。
4. `ArtifactType`。
5. `RoleProfile`。
6. `ProviderPolicy`。

### 4.2 能力组合优先

Agent 不直接绑定工具，Agent 装备组件库。

```text
AgentSpec
-> equipped_libraries
-> ComponentLibrary
-> tool / skill / MCP / API / prompt / script runner / provider
```

这样同一个 Agent 可以服务不同领域：

| Agent | 在内容生产中 | 在研究分析中 | 在销售运营中 |
|---|---|---|---|
| `research-agent` | 采集官方信息 | 收集研究资料 | 收集客户和竞品信息 |
| `writer-agent` | 写 MD 母稿 | 写分析报告 | 写销售话术 |
| `review-agent` | 审核事实和发布风险 | 审核引用和证据 | 审核合规话术 |

### 4.3 工作流模板可安装可复制

MVP 不把模板写死进代码。

模板来源：

1. builtin template。
2. local project。
3. local registry。
4. GitHub repo。
5. future cloud registry。

模板状态：

```text
draft / experimental / stable / deprecated / blocked
```

### 4.4 页面由视角驱动

不同岗位看到同一运行事实的不同投影。

| RoleProfile | 默认关注 |
|---|---|
| operator | 待处理、Run 状态、恢复动作 |
| editor | 文稿、审核、事实链、发布包 |
| designer | 视觉资产、Prompt、变体、版本 |
| researcher | 资料、证据、引用、分析报告 |
| manager | 成本、风险、进度、吞吐 |
| developer | Spec、Trace、Adapter、错误栈 |

## 6. P3 验收标准

P3 完成后必须能回答：

1. 如何用同一套模型表达内容生产、生图、剧本、研究、销售运营。
2. 首页、Run、Attention、Agent Collaboration 分别读取哪些 API。
3. Local Sidecar 负责什么，未来 Cloud Control Plane 负责什么。
4. Agent、Tool、Skill、MCP、Provider 如何通过组件库组合。
5. MVP 第一阶段具体做哪些任务，哪些不做。

## 7. 默认决策

| 决策 | 默认值 |
|---|---|
| 第一版运行形态 | 本地 Web + Node.js Local Sidecar |
| 第一版数据存储 | YAML/JSON/JSONL + manifest |
| 第一版工作流样本 | `content-production-v0` |
| 第一版模板扩展 | DomainPack + WorkflowTemplate |
| 第一版 Agent 扩展 | AgentSpec + ComponentLibrary |
| 第一版 Provider 扩展 | ProviderPolicy + Runtime Adapter metadata |
| 商业化后端 | P3 只定义演进边界，不锁死 Node.js |
