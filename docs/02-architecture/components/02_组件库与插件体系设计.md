# 02_组件库与插件体系设计

## 1. 设计目标

Miracle 的能力体系要同时满足两类用户：

- 普通用户：选择推荐工作流，不需要理解每个 tool、skill、provider。
- 高级用户：可以自由组合节点、skill、tool、MCP、prompt、provider 和 agent。

因此系统采用“组件单元 -> 组件库 -> 工作流节点”的三层结构。

```text
ComponentSpec -> ComponentLibrary -> NodeSpec -> WorkflowSpec
```

## 2. 为什么不把所有东西都节点化

如果每个 skill、tool、prompt、provider 都直接变成节点，系统会很灵活，但使用成本极高。用户每次启动任务都要处理大量低层配置。

Miracle 的默认策略是：

- 节点表达任务语义。
- 组件库表达能力组合。
- 组件表达可替换能力单元。
- Provider 表达 AI 能力来源。

例如：

```text
节点：生成 MD 母稿
组件库：内容母稿与平台分发组件库
组件：content-packaging skill + 母稿 prompt + 事实安全检查 + 平台模板
Provider：Codex / Claude Code / OpenAI API / Anthropic API
```

## 3. 组件类型

| 类型 | 定义 | 示例 |
|---|---|---|
| `skill` | 一组可复用流程指令、脚本、模板和参考资料 | content-packaging、tts-caption-workflow |
| `tool` | 单个可调用工具 | web search、browser、shell、image generation、ffprobe |
| `mcp_tool` | 通过 MCP 暴露的工具能力 | Pencil MCP、filesystem MCP |
| `prompt` | 可版本化提示词 | 母稿生成 prompt、分镜 prompt、审核 prompt |
| `script_runner` | 本地或远程脚本执行器 | TTS runner、storyboard adapter、render runner |
| `api_provider` | 官方或第三方 API 服务 | OpenAI、Anthropic、火山 TTS、Google |
| `runtime_adapter` | 智能体平台适配器 | Codex、Hermes、OpenClaw、Claude Code |
| `template` | 内容、视频或任务模板 | 资讯生产模板、短视频脚本模板 |
| `validator` | 质量或状态检查器 | 来源核验、字幕同步、ffprobe 检查 |

## 4. 组件库类型

### 4.1 官方源采集组件库

用途：采集 L1/L2 官方源、归档 Raw Item、保留访问失败和待确认状态。

包含：

- 官方源采集 skill。
- 来源等级规则。
- web/search 工具。
- Raw Item 模板。
- 访问失败记录器。
- 去重辅助组件。

推荐 Agent：情报 Agent。

推荐节点：Flow A。

### 4.2 事实清洗核验组件库

用途：把 Raw Item 清洗为 Clean Event，判断可信等级和可发布边界。

包含：

- 清洗核验 skill。
- L1-L4 来源规则。
- 证据链检查器。
- 观察池模板。
- 风险标注组件。

推荐 Agent：清洗 Agent、核验 Agent。

推荐节点：Flow A。

### 4.3 内容母稿与平台分发组件库

用途：生成 MD 母稿、标题、平台发布包、短视频口播、小红书轮播、知乎/公众号版本。

包含：

- 内容包装 skill。
- 爆点选题规则。
- 母稿模板。
- 平台改写模板。
- 标题库生成 prompt。
- 事实安全写作 validator。

推荐 Agent：主编 Agent、内容 Agent、分发 Agent。

推荐节点：Flow B、Flow G。

### 4.4 Pencil 原型组件库

用途：在内容母稿、视频分镜或产品方案前先做视觉/结构原型。

包含：

- Pencil MCP。
- 原型任务 prompt。
- 画布对象到 workflow node 的转换规则。
- 截图和设计说明导出器。

推荐 Agent：原型 Agent。

推荐节点：

- `prototype.pencil`
- `visual_planning`
- `storyboard_prototype`

### 4.5 TTS 字幕组件库

用途：配音脚本、TTS、字幕、音频 manifest、真实时长回写。

包含：

- TTS 字幕 skill。
- TTS provider 策略。
- voice profile。
- 字幕导出器。
- audio manifest validator。
- 听审记录模板。

推荐 Agent：配音 Agent、TTS/字幕 Agent。

推荐节点：Flow D。

### 4.6 HyperFrames 视频组件库

用途：生成横版/竖版 HyperFrames 工程、视觉审看版、最终渲染和交付说明。

包含：

- HyperFrames skill。
- GSAP 动画能力。
- lint / inspect / render runner。
- 字幕安全区检查。
- ffprobe 检查器。
- render manifest。

推荐 Agent：视觉视频 Agent、音画整合 Agent。

推荐节点：Flow E、Flow F。

### 4.7 审计复盘组件库

用途：发布前质检、审计日志、版本迭代、任务 trace、进化建议。

包含：

- 复盘 skill。
- task_trace schema。
- task_events schema。
- 质量检查表。
- 进化建议模板。

推荐 Agent：审核 Agent、复盘 Agent。

推荐节点：审核门、Flow G、Evolution。

## 5. 组件库装备机制

Agent 可以装备一个或多个组件库：

```yaml
agent_id: video-agent
equipped_libraries:
  - hyperframes-video-library
  - tts-caption-library
allowed_runtime_adapters:
  - codex
  - claude_code
allowed_providers:
  - openai
  - local_script
```

装备规则：

- Agent 装备组件库后，获得该库的默认 skill、tool、prompt、validator 和 provider 推荐。
- 节点仍可覆盖组件库默认配置。
- 高风险组件需要权限声明，例如写文件、调用付费 API、访问私密数据。
- UI 应显示 Agent 当前装备，而不是只显示 Agent 名称。

## 6. 插件与组件库的关系

Miracle 中“插件”是可安装、可启用、可更新的外部能力包；“组件库”是系统内部可组合的能力集合。

一个插件可以提供多个组件：

```text
Pencil 插件
-> Pencil MCP component
-> design screenshot component
-> prototype-to-node converter
-> visual planning prompt
```

一个组件库可以组合多个插件能力：

```text
视觉策划组件库
-> Pencil 插件
-> image generation tool
-> design prompt
-> asset board template
```

## 7. 权限与安全边界

每个组件必须声明：

- 是否读文件。
- 是否写文件。
- 是否调用外部 API。
- 是否需要密钥。
- 是否产生大文件。
- 是否可能消耗付费额度。
- 是否允许自动执行。
- 是否需要人工确认。

示例：

```yaml
security:
  file_read: true
  file_write: true
  external_network: true
  paid_api: true
  secret_required:
    - VOLC_TTS_API_KEY
  approval_required_before_run: true
  approval_required_before_downstream: true
```

## 8. 组件版本与升级

组件和组件库都必须版本化：

```yaml
id: content-packaging-library
version: 0.1.0
status: stable
changelog:
  - 0.1.0: first imported from 热点工具更新
```

状态：

| 状态 | 含义 |
|---|---|
| `draft` | 草案，不能自动进入正式工作流。 |
| `experimental` | 可在沙盒或小样任务中使用。 |
| `stable` | 可作为推荐组件库。 |
| `deprecated` | 不推荐新任务使用。 |
| `blocked` | 存在安全或质量问题，禁用。 |
